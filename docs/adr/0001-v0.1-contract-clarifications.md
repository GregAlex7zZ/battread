# ADR 0001: Clarify the v0.1 scientific and implementation contracts

**Status:** Accepted before implementation  
**Date:** 2026-10-04  
**Specification version:** 0.1

## Context

The original design establishes a small canonical schema and conservative
scientific behavior. Review identified contracts that could still produce
different outcomes between otherwise reasonable implementations. The user
authorized clarification of those contracts before library code is written.

This record explains the decisions. Their operative requirements are also
included in the [technical specification](../specification/TECHNICAL_SPECIFICATION.md),
[API specification](../architecture/ARCHITECTURE_AND_API.md),
[recognition specification](../specification/COLUMN_RECOGNITION.md), and
[acceptance plan](../testing/TESTING_AND_ACCEPTANCE.md).

## 1. Capacity reconstruction

- Incremental capacity requires verified reader alignment or an explicit
  `capacity_interval="previous"` or `"next"`. The increment belongs respectively
  to the interval ending or starting at its row. Previous alignment leaves the
  first current unavailable; next alignment leaves the last unavailable.
- Cumulative differentiation uses the previous adjacent original row and leaves
  the first current unavailable. A non-`None` interval option is invalid when
  cumulative reconstruction is selected.
- An explicit `capacity_kind` requires an explicitly mapped capacity column and
  overrides that column's inferred semantics. It does not replace usable direct
  current or waive dimensional/reset safety checks.
- Declaring generic cumulative signed capacity asserts a continuous signed
  charge-transfer quantity. A negative change can be discharge and is not proof
  of a reset. Known resets or violations of established cumulative charge or
  discharge semantics cause failure in v0.1; no reset repair is attempted.
- Reconstruction does not bridge missing source rows. Invalid intervals retain
  their rows with missing reconstructed current and warnings. If the complete
  source provides no finite reconstructed current, reconstruction fails.
- Measured-current selection depends on semantics, compatible units, and numeric
  compatibility. Missing values, including an all-NaN selected column, do not
  trigger capacity substitution. This keeps strategy selection independent of
  a sampled region or chunk size.

**Reason:** Increment alignment changes the numerical answer, while signs and
magnitudes alone cannot distinguish valid discharge from a reset.

## 2. Time validation and merge

- A valid dataset is nonempty and has at least one finite time. Its first finite
  time becomes zero, and leading/internal/trailing `NaN` rows are retained.
  Infinity is invalid in all canonical columns.
- Finite times must be non-decreasing even when missing rows occur between them.
- Merge endpoints are the previous last finite time and the next first finite
  time. Bridge intervals use adjacent original finite rows only: search backward
  in the preceding dataset, then forward in the following dataset.
- Do not infer a sampling interval across a missing-time row. For example,
  merging `[0, NaN, 10, 10]` with `[0, 5]` uses the following 5-second interval
  and produces `[0, NaN, 10, 10, 15, 20]`.
- Empty merge collections or invalid inputs fail; a singleton returns an
  independent canonical DataFrame. Inputs are never mutated.

**Reason:** Missing timestamps do not establish a sampling interval. Using
finite endpoints still preserves the explicit sequence and all source rows.

## 3. Generic parsing and inspection

- `sep`, `decimal`, `encoding`, `header`, and `skiprows` are explicit overrides
  shared by `read()`, `iter_read()`, `inspect()`, and the source side of
  `convert()`. They take precedence over detection.
- `autodetect` controls semantic column/unit recognition, while unspecified file
  structure may still be detected. Uncertain parsing requires an explicit
  override; invalid options and unsupported reader options fail clearly.
- Duplicate labels retain positional identity and require positional selection
  when a name matches multiple columns. Unit prefixes retain meaningful case.
- Inspection reports ambiguous/unresolved candidates without requiring a
  successful conversion. It does not certify unexamined rows.
- `applied current` is removed from strong generic measured-current aliases:
  vendor evidence or an explicit selection must establish its meaning.

**Reason:** Users need deterministic controls for recoverable detection failures
and a preview API that remains useful when recognition is ambiguous.

## 4. Streaming completion and output publication

- `iter_read()` uses a reference default of 250,000 rows and retains operation
  state, including the original time origin and one-row lookahead when needed.
- The iterator may raise after yielding earlier chunks. Complete-file success
  requires exhaustion and whole-source checks.
- `convert()` and `write()` use a temporary file in the destination directory.
  Publication occurs only after all checks and writing succeed; failure removes
  the operation's temporary file and preserves an existing destination.
- Chunk equivalence covers values, failures, warning categories, affected
  columns, and aggregate affected-row counts. Warning emission count may vary.

**Reason:** Late failures must not leave a destination that appears to be a
successfully validated scientific output.

## 5. Acceptance and v0.1 scope

- Require independently verified fixtures for every advertised format:
  `.mpr`, `.mpt`, `.nda`, and `.ndax`.
- Gate reset rejection, invalid/missing intervals, duplicate names, parsing
  overrides, infinities, empty/all-missing time, and scientific conditions
  directly at chunk boundaries, including chunk size 1.
- Parquet, CSV, and TXT are required outputs. Reference text output is UTF-8,
  decimal point, header present, and no index; CSV uses commas and TXT tabs.
- Excel, custom destination text dialects, `convert_many()`, and streaming
  merge-to-file are deferred beyond v0.1. In-memory merge and single-source
  streaming conversion remain required.

**Reason:** Acceptance must cover the actual support claims, while keeping the
first implementation focused on its specified scientific ingestion behavior.

## 6. Repository identity and release metadata

- Use `battread` for both distribution and import names, matching the project
  folder. Root `README.md`, `pyproject.toml`, `LICENSE`, and
  `THIRD_PARTY_NOTICES.md` replace the misplaced landing/packaging documents.
- Keep GPL-3.0-or-later. The GPL text is moved verbatim. Declare the SPDX license
  expression and explicit license file; omit the deprecated license classifier.
- Require Hatchling >=1.27.0 for the selected metadata format, following
  [PyPA's supported-version guidance](https://packaging.python.org/en/latest/guides/writing-pyproject-toml/#license).
- Do not invent author identities or repository URLs. Maintainers provide those
  before publication. Preliminary third-party notices record planned
  dependencies; dependency compatibility and full release attribution remain
  an implementation/release audit.

**Reason:** The documents and packaging should identify the intended project
without suggesting that an implementation, publication, or dependency audit
already exists.

## Consequences

These decisions refine the preimplementation v0.1 contract and do not change the
three canonical columns or add electrochemical analysis. Implementers must add
the corresponding acceptance tests. No library source is introduced by this
documentation change.
